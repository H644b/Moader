# v0.2.6-rc.1 hold-R candidate

This local candidate addresses reports that a successful Seedsow FS installation is followed by two native-game launches with **R** but no hbmenu. The installation receipt proves HEN reached its waiting state; it does not prove the later game-entry path.

The matched HEN now reads fresh R samples from the enabled standard controller styles as well as SystemExt. During first-launch policy capture, it waits for a still-closing Seedsow application to leave PM before binding the native game. The full regular kaiHEN file set, game loader, hbmenu, OunceShell and Moader app/resident remain in the backend kit. RO and bootstrap bytes are unchanged.

The pinned native build, patch replay, HEN host regressions and installer/setup checks pass. The build proof marks `console_retest_passed: false`. Local candidate installation attempts have stopped in FS acquisition before HEN launched; they do not test this fix. A tester without an existing `/kaihen/bin/game/main.npdm` should use one fresh full reboot, install once, close Seedsow, then hold **R** through the first and second launches of the same native Switch 2 game. If hbmenu does not appear, preserve the GUI log and run directory privately. Do not rerun FS or HEN on a failed or uncertain boot.

This candidate is not a verified public release. [Seedsow setup](../SEEDSOW.md) · [validation record](../VALIDATION.md#hold-r-candidate-after-v025).
