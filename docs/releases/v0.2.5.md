# Moader v0.2.5 — resident BSD session budget

The resident now requests one BSD operation session instead of the pinned SDK default of three. The SDK also opens a monitor session, so the resident's planned BSD session use falls from four to two. Its web listener, NIFM, UDP instance lock, filesystem routing and matched kaiHEN components remain in place. This addresses the session pressure reported in [issue #14](https://github.com/H644b/Moader/issues/14).

Follow the [installation guide](../INSTALLATION.md) for a new boot or [reload the resident](../PLUGIN_RELOAD.md#use-it) if the matching protocol-7 kaiHEN and filesystem runtime are already running. Replacing an NSO on SD alone does not replace the running service. Do not reuse a Seedsow or other native FS session after a failed or completed attempt.

## Verification

The exact resident NSO (`6b1895c30855e777e26eee30c7ef5cba5d986e4ae0bbec72078a9e5a54bd5b18`) passed a cross build and the sanitizer-backed startup, reload, web and teardown fixture. It was then copied to SD with full readback and reloaded on a fresh Seedsow Demo boot using the existing matched backend. The owner reported that Minecraft for Switch 2, which had crashed after their v0.2.0 install, entered a world and remained running. The resident returned HTTP 200 while the game was open. The v0.2.5 app NRO (`290dcde96a905691476cb443e16b8b5a07e16919bd0e8d7bf190d89933d1c565`) was separately staged with full readback and opened on the same boot; it displayed v0.2.5 and showed runtime and FS connected. Its only binary change from the published v0.2.0 NRO is the NACP version digit.

The earlier crash code was not captured, and Splatoon 3 was not available for this check. This result does not prove the crash's exact cause or cover every game. A fresh install of the complete v0.2.5 kit, the Seedsow full-game route and Linux/WSL2 live-console routes remain untested.
