# Moader v3.0.0 — Seedsow standalone kit

The backend kit now ships the pinned on-console Seedsow A/B implementation and a source-built standalone bootstrap. After one-time SD and profile-save preparation, **A** runs the Moader FS adapter and kaiHEN on the console; **B** runs the regular upstream Seedsow Lua chain with the same SD files. The existing PC-driven Seedsow, SmileBASIC and experimental CivSwitch setup paths remain available.

## Downloads

- [Moader-v3.0.0.zip](https://github.com/H644b/Moader/releases/download/v3.0.0/Moader-v3.0.0.zip): console app and matching resident plugin in SD layout.
- [Moader-backend-v3.0.0.zip](https://github.com/H644b/Moader/releases/download/v3.0.0/Moader-backend-v3.0.0.zip): backend source and tools, complete regular patched kaiHEN bundle, and `prebuilt/standalone-bootstrap/bootstrap.bin` with its source-build receipt.
- [Moader.nro](https://github.com/H644b/Moader/releases/download/v3.0.0/Moader.nro) and [moader.nso](https://github.com/H644b/Moader/releases/download/v3.0.0/moader.nso): standalone app and resident binaries.
- [SHA256SUMS.txt](https://github.com/H644b/Moader/releases/download/v3.0.0/SHA256SUMS.txt) and [release-manifest.json](https://github.com/H644b/Moader/releases/download/v3.0.0/release-manifest.json): asset checksums, exact component identities and source commit.

Start with [Installation](../INSTALLATION.md) or the [on-console Seedsow guide](../SEEDSOW_STANDALONE.md). **The v3.0.0 kit cannot prepare A from public files alone:** the Moader FS payload generator requires the exact qualified local FS capture. No console-derived FS bytes, save or private log is in the download. The prebuilt standalone bootstrap avoids a local SDK build when that qualified capture is available.

## Validation scope

The standalone bootstrap (`f3f4305d53d5e3da9dac4b054acdcdc3c2addb436d813b2e08c2a9f32f1733ea`) was rebuilt from the pinned native source after reproducing the regular release bootstrap. The adapter has SHA-256 `244b57ab97fd9fa160e522f1387d64747d4b5999f1a28f71a1429135d01dfce2`. One fresh Profile B Seedsow Demo **A** boot with those exact components reached `KH READY`, with 19 FS hooks and a running Moader plugin. On that same boot, a read-only check found a current, CRC-valid FS acknowledgement matching the catalogue epoch and generation with result `0x0`. On a separate boot, the owner reported **B** reaching hbmenu with Moader disconnected, as intended for that route. [Detailed device record](../VALIDATION.md#seedsow-standalone-host-preparation).

The v3.0.0 app and resident were rebuilt with 3.0.0 version text; the underlying resident service and native FS adapter logic are unchanged. After publication, both exact v3 binaries were staged on the same console and independently read back by FTP SHA-256. The owner then reported a fresh Profile B A boot reaching `KH READY` and Moader v3.0.0 showing both runtime and FS connected. This is a console report for the exact v3 pair; no same-boot catalogue or acknowledgement was fetched for that run. A fresh preparation from the public v3 kit, another v3 A boot, other consoles and physical mod reads remain unverified. The release manifest retains its conservative packaging-time hardware flag.
