# RO service

First C++ port of the working kaiHEN RO frontend. It builds an NSO at
`build/main` and serves `ldr:ro` in native service spaces 1 and 2.

The first implementation supports Initialize, LoadNrr, UnloadNrr, LoadNro,
UnloadNro, and the pointer-buffer query used by libnx service initialization.
It has no resident network thread or BSD setup. Each client supplies its
own process handle through Initialize. Private command 65001 accepts the
bootstrap's copied HEN control session; command 65004 asks HEN for an
independent homebrew session and returns its client handle. RO copies the
caller process handle received during Initialize into HEN when creating that
session; homebrew obtains it through HEN command 18. RO keeps its
control connection independently of individual loading clients.

The native bootstrap starts RO; see the top-level README.

## Build and tests

From kaiHEN:

```sh
make -C ro        # with the Switch 2 devkit installed
sh ro/test.sh
```

`make` in kaiHEN builds all of it; kaiHEN's Dockerfile builds it in the devkit's
image. RO is C++20 with exceptions and RTTI disabled. Build outputs stay
under `ro/build/`.

Host tests cover requests generated by libnx's CMIF encoder, NRO header
layout, client initialization and process-handle ownership, NRO/NRR and JIT
dispatch with a mocked mapping backend, and the NRO mapping itself against a
mocked kernel (address search, retries, guard pages, permissions and
rollback). They do not prove kernel mapping or service registration on the
console. The AArch64 NSO build passes with warnings treated as errors.

## Source layout

- `main.cpp`: service ports, accepted sessions, and server loop.
- `handle.hpp`: noncopyable ownership of server port/session handles.
- `results.h`: the results RO returns, named as Atmosphere names RO's.
- `wire.cpp`: RO requests and replies using libounce-nx HIPC/CMIF facilities.
- `control.cpp`: retained HEN connection and fresh client-session courier.
- `session.cpp`: client process context, NRR records, JIT commands, and
  command dispatch.
- `mapping.cpp`: NRO address search, mapping, permissions, cache
  publication, and teardown.
- `image.cpp`: the existing supported NRO layout.
- `fs_memory.cpp`: the private system-space `ro:dmnt` endpoint keeps FS code
  reads and writes for kaiHEN (`../include/ro_dmnt.h`) and RO diagnostics.
  The app-space `mfs:ro` endpoint gives the standalone Seedsow adapter only
  its bounded, PID-bearing FS process commands. Each request must carry a
  copied handle whose program ID is FS; the adapter also binds the reply to
  the current replacement RO PID and verifies the transferred FS PID before
  any code write. The system-space endpoint retains its existing behavior.
  If stock RO left a stale `ro:dmnt` registration, the replacement releases
  that entry and retries; it does not unregister an app-space service.

Mapping cleanup remains explicit because unmapping can fail. As in the
source implementation, a failed partial cleanup retains its ownership
record; closing the client does not silently discard it. Successfully loaded
images are not unmapped merely because a client closes its service session.

The inherited mapper supports contiguous, page-aligned NRO0 segments. It is
not a general ELF loader, and NRR registration here retains the existing
homebrew behavior rather than adding stock signature verification.
